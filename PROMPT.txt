
# PROJETO

Crie um software desktop profissional para Windows chamado provisoriamente:

# Leccor Windows Health Center

O software deve realizar uma **auditoria completa do computador**, detectar problemas de hardware, Windows, aplicativos, armazenamento, processos, drivers, rede e performance e permitir corrigir problemas de maneira segura.

O objetivo é criar uma ferramenta semelhante conceitualmente à combinação de:

* diagnóstico do Windows;
* Gerenciador de Tarefas;
* Resource Monitor;
* Event Viewer;
* Storage Sense;
* ferramentas Sysinternals;
* SFC/DISM/CHKDSK;
* análise SMART;
* gerenciador de inicialização;
* diagnóstico de rede;
* análise de aplicativos;
* limpeza segura;
* monitor de hardware;
* sistema de relatórios.

Porém tudo centralizado em uma única interface moderna e simples.

---

# 1. OBJETIVO PRINCIPAL

O aplicativo deverá conseguir executar:

**VARREDURA → DIAGNÓSTICO → CLASSIFICAÇÃO → CORREÇÃO → VALIDAÇÃO → RELATÓRIO**

O software NÃO deve funcionar como um "PC Cleaner" genérico.

Toda recomendação deve possuir:

* evidência;
* motivo;
* impacto;
* risco;
* ação recomendada;
* possibilidade de rollback quando aplicável.

O software nunca deve inventar problemas para aumentar artificialmente a quantidade de erros encontrados.

# 6. NÍVEIS DE RISCO

Toda ação deve possuir:

```text
SAFE
LOW
MEDIUM
HIGH
CRITICAL
```

## SAFE

Pode ser executada automaticamente.

Exemplo:

* limpar cache temporário comprovadamente descartável.

## LOW

Baixo risco e facilmente reversível.

## MEDIUM

Pode alterar comportamento do sistema.

Exigir confirmação.

## HIGH

Pode afetar:

* boot;
* drivers;
* serviços;
* rede;
* aplicações.

Exigir confirmação explícita.

## CRITICAL

Pode envolver:

* partições;
* corrupção;
* perda de dados;
* hardware falhando.

Não executar automaticamente.

# 60. AGENDAMENTO

Posteriormente permitir:

```text
Executar diagnóstico:

○ Manualmente
○ Diariamente
○ Semanalmente
○ Mensalmente
```

Utilizar Windows Task Scheduler ou mecanismo apropriado.

O monitoramento permanente deve ser opcional.

---

# 61. MODO PORTABLE

Arquitetura deve permitir futuramente:

```text
LeccorWindowsHealthCenter.exe
```

sem instalação completa.

Funcionalidades dependentes de serviços persistentes podem ficar indisponíveis nesse modo.

---

# 62. INSTALADOR

Criar instalador profissional.

Permitir:

* instalar;
* atualizar;
* reparar instalação;
* desinstalar.

A desinstalação deve remover arquivos do aplicativo sem remover relatórios/backups do usuário sem confirmação.

---

# 63. SEGURANÇA DO SOFTWARE

Considere o aplicativo uma ferramenta privilegiada.

Aplicar:

* princípio do menor privilégio;
* validação de inputs;
* proteção contra command injection;
* paths seguros;
* validação de executáveis;
* assinatura de código preparada;
* comunicação segura entre processos;
* ACLs adequadas;
* proteção dos diretórios de backup.

Nunca utilizar entrada do usuário diretamente em:

```text
cmd.exe
powershell.exe
Registry
WMI
filesystem
```

sem validação.

---

# 64. ARQUITETURA DE PRIVILÉGIOS

Para operações administrativas, considere separar:

```text
LeccorWindowsHealthCenter.exe
          ↓
LeccorWindowsHealthCenter.Elevated.exe
```

O processo principal permanece sem privilégios administrativos.

Somente operações específicas utilizam processo elevado.

Criar comunicação IPC autenticada e limitada.

# 71. DEFINITION OF DONE

Uma funcionalidade somente é considerada concluída quando possuir:

* implementação;
* tratamento de erro;
* logging;
* cancelamento;
* teste;
* documentação;
* validação de permissões;
* análise de risco;
* interface;
* evidências;
* resultado compreensível para usuário comum.

---

# 72. REQUISITO FUNDAMENTAL

Nunca mostrar apenas:

> "Encontramos 154 problemas."

Mostrar:

> "Encontramos 3 problemas confirmados e 8 recomendações."

Cada problema precisa ser explicável.

O usuário precisa conseguir clicar e descobrir:

**O que aconteceu?**

**Como sabemos disso?**

**Qual impacto?**

**Como corrigir?**

**Qual risco da correção?**

**Posso desfazer?**

6. Infrastructure;

# 75. PRIMEIRA EXECUÇÃO DO AGENTE

Comece agora criando a estrutura do projeto.

Antes de implementar scanners específicos:

0. gere `CONTEXTO.md`;
0. gere `DOCUMENTACAO.md`;
0. gere `PASSOS.md`;
0. gere `README.md`;
1. gere `ARCHITECTURE.md`;
2. defina os projetos da solution;
3. configure Dependency Injection;
4. configure logging;
5. configure SQLite;
6. crie interfaces dos scanners;
7. crie `Finding`, `Evidence`, `Metric` e enums;
8. implemente `ScanOrchestrator`;
9. implemente `RuleEngine`;
10. implemente estrutura inicial do `RepairEngine`;
11. crie dashboard inicial;
12. faça o primeiro build;
13. execute testes;
14. corrija todos os erros encontrados.

Depois comece o **MVP 1**.

Não pule diretamente para otimizações ou correções do Windows antes que a infraestrutura de diagnóstico, evidências, risco, logs e rollback esteja corretamente implementada.

O princípio central de todo o projeto é:

# MEDIR → DETECTAR → COMPROVAR → EXPLICAR → CORRIGIR → VALIDAR → DESFAZER SE NECESSÁRIO

Crie um software tecnicamente confiável, transparente e seguro, e não apenas mais um "PC Cleaner".
